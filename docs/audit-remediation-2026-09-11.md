# Исправления аудита 11 сентября 2026 года

База изменения: `e850fb9f8e9f44eed7d7e46152b923709875b7cb` в
`fireostendere/custom_opencode`. Это изменение существующего проекта, не новый
оркестратор и не замена OpenCode. Native CLI закреплён на
`@opencode-ai/cli@0.0.0-beta-18743`.

## Что изменилось для модели

Пользовательские сообщения, цитаты и результаты инструментов больше не проходят
общую очистку XML. Веб-транспорт не вставляет повторный контекст в историю и не
повторяет отклонённый запрос по старому API с потерянными инструкциями.
Динамический контекст собирается в native hook; текущие доказательства получают
место до старой памяти. Обязательные инструкции не отбрасываются молча.

Скрытый потолок custom context budget в 48 000 токенов удалён. Лимиты берутся из
пары provider/model текущего native-события, а не из соседней задачи или
общего кэша другой сессии. Проверка `small → large → small` также использует
одинаковый model ID с разными лимитами и не меняет общий каталог.

**Расчёт custom budget и фактическая native compaction — разные контракты.**
Поля `targetRatio` и `maxInputTokens` управляют расчётом/диагностикой надстройки,
но не являются новой настройкой алгоритма upstream. В native-пути компакцией
владеет сам движок; hook не вызывает повторный HTTP compact, пока native готовит
контекст. Установщик задаёт `compaction.auto=true`, `buffer=2048`, `keep=4096`
вместо `buffer=24000`, `keep=12000`. Большой прежний buffer был несовместим с
некоторыми малыми входными окнами. Эти числа — резерв и сохраняемый хвост, не
фиксированный размер окна. Корректность сохранения смысла реальной моделью после
компакции не доказывается арифметическим unit-тестом и требует отдельного replay.

При большом выводе сохраняются полный артефакт, диагностический конец и начало.
Модель получает настоящий native-инструмент `runtime_artifact_read` с диапазоном
и поиском. Доступ проверяется по сессии до чтения; аргумент не может подменить
native session ID. Артефакт другой сессии не разрешается просто по знанию ID.
Безопасный polling статуса не считается повторной записью, включая
namespaced-инструменты `fabric_fabric_job_status` и `fabric_fabric_job_result`.
Rate limit использует атомарное скользящее временное окно.

## Токены: измерение и ограничения

Для queued-задачи baseline снимается при фактическом dispatch. Финализация
идемпотентна; история читается постранично с устранением пересечений.
Отсутствующий usage обозначается как неизвестный, а не бесплатный.
Полезные repair/recovery не классифицируются как потери без отдельной причины.

`execution_ledger.py` хранит root budget, привязку native user turn/child session,
отдельные HTTP-попытки, provider/model и наблюдённый usage. У всех стадий одной
задачи и её дочерних исполнителей общий бюджет. Настоящий новый пользовательский
ход получает новый root; старые дочерние сессии не присоединяются к новой задаче
по совпавшей рабочей директории.

Настройка по умолчанию:

```dotenv
OPENCODE_ROOT_BUDGET_JSON='{"calls":128,"outputTokens":1048576,"toolAttempts":1024,"seconds":7200,"finishTokens":4096}'
```

Это 128 обычных HTTP-запросов и не более одного дополнительного запроса завершения
без инструментов, общий резерв output/reasoning, 1024 попытки инструментов и
7200 секунд обычной работы. Состояние исчерпания сохраняется в checkpoint.
Сетевые повторы тоже расходуют call budget. Отмена потока не теряет уже полученный
usage: он фиксируется на завершающем событии, а не только на закрытии reader.
Неизвестный результат сохраняет резерв output, а не освобождает его под видом
нулевой стоимости. Единственный владелец HTTP retry — native engine; второй
скрытый цикл повторов Gemini отключён на рабочем пути.

**Резерв токенов не равен списанию провайдера.** Input, cache, output и reasoning
наблюдаются отдельно; reasoning не прибавляется повторно к включающему его
completion count. Встроенный hard limit не является универсальным долларовым
или input-token cap. Цены неизвестной модели не выдумываются. Native session
statistics и provider request ledger нельзя складывать: это перекрывающиеся
представления. Реальные счета и экономия в процентах в этом прогоне не измерялись.

## MCP и политика выполнения

Для больших активных профилей `mcp_discover` находит подходящие операции и
открывает до восьми полных схем на следующем model step. Рабочий набор заменяется,
а не постепенно разрастается до всего каталога. Вызов выбранного инструмента
идёт прежним native-путём с валидацией и разрешениями; универсального обходного
`execute-anything` прокси не добавлено. Порог отложенной загрузки — более восьми
инструментов либо более 12 000 символов сериализованных схем. Это не обещание
верхней границы каждого возможного большого одиночного input schema.

Для профилей native Code Mode по-прежнему отключается намеренно: его глобальный
snapshot не изолирует разные наборы прав сессий в закреплённой версии. Экономия
достигается отложенными схемами, а не ослаблением профилей. Нормализованные имена
серверов проверяются на коллизии до установки. Namespace сервера зарезервирован
для его инструментов; нативные плагины не должны создавать пересекающиеся
модельные имена. Неизвестные возможности нельзя объявлять разрешёнными только
по их описанию.

`custom-opencode-policy` — отдельный аутентифицированный listener на loopback,
по умолчанию порт 4099. Остановка необязательного web UI не отключает политику
и не превращает fail-closed в fail-open. Установщик и native wrapper обеспечивают
его запуск; общая SQLite lease допускает одного владельца восстановления и
очереди. Завершение тестового сервера останавливает worker до удаления базы.

```bash
custom-opencode-policy ensure
custom-opencode-policy status
custom-opencode-policy stop
```

`stop` намеренно делает policy-зависимые действия недоступными до следующего
запуска. Это не переключатель обхода прав. Токен политики, lock и логи приватны;
административные HTTP-операции не переносятся в открытый web listener.

## Воспроизведение

Основной прогон сохраняет каждый из 25 suite results и логи, не складывая
повторяющиеся вложенные тесты в искусственно большой итоговый счётчик:

```bash
python scripts/audit-regression.py --output /tmp/custom-opencode-regression
python scripts/install-native-regression.py --output /tmp/custom-opencode-native-install
python scripts/native-budget-regression.py --retry-once --output /tmp/custom-opencode-native-wire
python scripts/sandbox-preflight.py
python scripts/tool-fabric-smoke.py
```

Нужны Python, Node 22, указанные requirements и браузер Playwright 1.57.0.
`OPENCODE2_BIN` указывает на настоящий закреплённый CLI. Clean-install harness
может скачать официальные зависимости либо использовать `--cli-prefix` и
`--ponytail-url` с заранее полученными неизменёнными пакетами. Режим `manual`
проверяет реальные процессы без подмены CLI и без заявления о проверке user-systemd.

Native-wire harness использует настоящий CLI, MCP stdio server и локальный
детерминированный HTTP provider: он проверяет протокол, не интеллект модели.
Вариант `--retry-once` возвращает один 503; запросы повторной попытки отражаются
отдельно. Следующий пользовательский ход проверяется в той же native-сессии.
Личные credentials, live RAG corpus и DipTrace ему не нужны.

На неподдерживающем ядре sandbox preflight возвращает `BLOCKED_ENV`, exit 77.
Основной contract-suite не выдаёт это за PASS. GitHub job `kernel-sandbox`
по-прежнему требует успешного настоящего запуска. Никакое отключение изоляции
ради зелёного статуса не предусмотрено.

## Защита основной ветки

`bash scripts/protect-main.sh fireostendere/custom_opencode` — явная отдельная
административная операция. Она требует существующего `gh` login с Administration
write, проверяет последние успешные результаты четырёх jobs именно на текущем
main и отказывается активировать защиту при старом PASS/новом FAIL, pending или
смене SHA. Затем включает strict required checks, обязательный PR, защиту для
администраторов, запрет force push и удаления. Наличие скрипта не заменяет
реальное состояние GitHub. Количество обязательных approvals равно нулю для
индивидуального проекта; сами checks не становятся необязательными.

Проверка намеренно красного PR и фактическое применение protection выполняются
в GitHub, не посредством mock-CLI. Патч не хранит и не добывает токены из других
приложений. Он также не пушит изменения и не перезаписывает удалённую main.
