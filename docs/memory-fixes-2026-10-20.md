# Исправления памяти — 20 октября 2026

Исходная версия аудита: `7cf32ed81a748da2eeb8de76ea07c315dc5856d0`.
Проверялись web-интерфейс, Python runtime и плагины этого репозитория.

## Что исправлено

| Участок | Причина роста | Изменение |
| --- | --- | --- |
| Вложения web | Второй `FileReader` и завершённые Promise сохраняли base64 после удаления вложения | Общий lifecycle чтения для `app.js` и `advanced-features.js`; завершённые операции удаляются, удалённые и отменённые вложения не возвращаются из поздних callbacks |
| История web | Параллельные загрузки обходили лимит кэша; удалённые сессии сохраняли transcript | LRU ограничен 12 сессиями, включая загружаемые; ответы проверяют identity записи; удаление очищает связанные данные |
| Git snapshots | Снимки и служебные карты росли с числом открытых worktree | LRU по числу проектов и размеру снимков; фоновые refresh проверяют identity и generation перед записью |
| Подсчёт usage | Каждая проверка прогресса держала всю историю и сериализованные сообщения | Агрегация по страницам, dedupe по ID и только последние 20 элементов подписи |
| Чтение артефактов | Маленький диапазон требовал чтения и распаковки всего файла | Потоковые диапазоны и поиск для обычных и gzip-файлов; ограничены также буферы очень длинных строк |
| D&D catalog | Для каждого набора аргументов сохранялся полный ответ | SHA-256 аргументов и ответа, канонический порядок ключей, LRU на 64 записи внутри сессии |
| `/goal` | При запуске в RAM загружались все завершённые цели | Постоянно загружаются активные цели; история читается по запросу и ограничена 32 записями |
| Provider fallback | Исходные тела запросов переживали отмену и некоторые пути без `http.response` | Ограничения по байтам, числу и времени; cleanup по abort, событиям сессии и dispose; корреляция сохраняется при замене `Request` плагинами |

Usage и чтение артефактов создавали временные пики. Остальные найденные
проблемы удерживали данные после окончания соответствующей операции.

## Лимиты

- Web history: 12 сессий. История выбранной сессии продолжает загружаться постранично.
- Git snapshots: по умолчанию 128 проектов и 16 MiB оценённого размера Python-объектов.
  Переменные `OPENCODE_GIT_CACHE_MAX_PROJECTS` и `OPENCODE_GIT_CACHE_MAX_BYTES`
  позволяют изменить эти пределы. Это бюджет кэша, а не ограничение RSS процесса.
- D&D catalog: 64 пары хэшей на сессию; общий существующий предел — 128 сессий.
- Goal history: 32 недавно запрошенные неактивные цели. Сохранённая история остаётся доступной.
- Provider fallback: не более 256 записей и 16 MiB исходных тел на плагин,
  срок хранения — 5 минут. Запрос, для которого нельзя сохранить fallback,
  отправляется без добавления необязательного tier/schema.

## Проверка

### Измерения до и после

Одинаковые синтетические сценарии выполнены на исходной и исправленной версиях.
Python измерен через `tracemalloc`; JavaScript — по heap после принудительной GC.
MiB здесь равен 1 048 576 байтам. Эти значения не включают всю нативную память процесса.

| Сценарий | До | После |
| --- | ---: | ---: |
| Usage: 4 000 сообщений, 16 KiB tool output в каждом, пиковая Python-память | 82,375 MiB | 3,752 MiB |
| Артефакт 32 MiB, вернуть 1 000 символов: plain, пиковая память | 64,009 MiB | 0,025 MiB |
| Тот же диапазон gzip-артефакта, пиковая память | 77,448 MiB | 0,159 MiB |
| 200 worktree по 1 000 длинных dirty paths: удержанная память снимков | 81,871 MiB | 15,972 MiB |
| 60 одновременных загрузок истории по 80 сообщений: число записей кэша после ответов | 60 | 12 |
| 100 attach/remove по 256 KiB: рост heap после GC | около 33,4 MiB | рост не обнаружен: 5,99 → 5,91 MiB |
| 1 000 различных catalog lookup с ответом около 44 KB: рост heap после GC | около 42,2 MiB | около 0,10 MiB |
| Запуск с 2 000 завершёнными целями: рост heap после GC | около 35 MiB | около 0,25 MiB |

В Git-сценарии исправленный кэш держал 39 тяжёлых снимков и одинаковые 15,972 MiB
после 100 и 200 разных worktree. Ограничение сработало по байтам раньше предела проектов.
Usage на 200 / 2 000 / 4 000 сообщениях дал пики 3,457 / 3,660 / 3,752 MiB:
в памяти остаётся страница и множество ID, без полного содержимого истории.

### Regression

Полный `scripts/verify.sh` прошёл до изменений и после объединения исправлений.
В интегрированной версии frontend memory suite прошла 19 сценариев,
backend memory suite — 19 тестов, plugin memory/lifecycle suite — все проверки.
Отдельный differential прогон потокового чтения совпал с прежней семантикой
на 5 000 вариантах текста, Unicode, line separators и границ буфера.

Все три memory regression входят в общий verifier:

```bash
node --expose-gc scripts/frontend-memory-regression.mjs
python3 scripts/memory-backend-regression.py
node --expose-gc scripts/plugin-memory-regression.mjs
bash scripts/verify.sh
```

Frontend regression загружает настоящие `app.js` и `advanced-features.js`
с общими DOM/event fixtures: attach/remove, ожидание чтения при отправке,
отмена, переключение и удаление сессий, поздние ответы, LRU и stream merge.
Python regression проверяет точные значения usage и подписи, диапазоны,
Unicode/newlines, gzip, поиск, размеры кэшей и гонки refresh.
Plugin regression проверяет удержание heap после GC, eviction, abort,
удаление сессий, dispose и сохранение fallback.
Проверки отмены покрывают также повторное открытие того же чата во время чтения
вложения и сброс плагина во время чтения ответа 400: поздней отправки или retry нет.

Эти проверки используют синтетические данные и не обращаются к платным моделям.
Измерения характеризуют конкретные сценарии, а не расход RAM на компьютере владельца.
Native OpenCode engine и реальный браузер не профилировались; тесты web работают
с DOM fixtures, а тесты плагинов — с fixtures событий и HTTP hooks.

## Применение

После слияния PR обновить установленную копию через `scripts/install.sh`
по [инструкции установки](installation.md). Установщик переносит изменения
web/runtime и плагинов в используемую конфигурацию. Уже запущенные процессы
и открытые страницы должны загрузить обновлённый код.
