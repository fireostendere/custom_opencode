## Исправлено

| Область | Причина | Изменение |
| --- | --- | --- |
| История web-чата | Принудительное обновление терялось, если предыдущая загрузка страницы ещё шла | Одно повторное чтение после текущего запроса, включая загрузку старых сообщений |
| Статус выполнения | Старый ответ `idle` мог скрыть Stop сразу после принятой отправки | Оптимистичный запуск сохраняется до подтверждения `busy` или пятисекундного допуска; после подтверждения `idle` завершает его сразу |
| Разрешения | Поздний ответ проверки риска мог относиться к другой сессии или другому запросу | Перед показом результата сверяются сессия и ID разрешения; параллельные проверки объединяются |
| Отправка prompt | Любой ответ 400/422 запускал повтор с другим форматом | Совместимый повтор остаётся только для ошибки формы запроса или отсутствующего endpoint |
| Список сессий | Повторяющийся cursor вызывал до 200 лишних страниц за одно обновление | Чтение останавливается при повторе cursor |
| SQLite-кэш | Чтение просроченной записи могло удалить свежую замену от другого потока | Удаление теперь условное по времени истечения той же просроченной записи |
| DnD HTTP hook | Полная история запроса глубоко копировалась для замены трёх полей; последнее user-сообщение искалось дважды | Копируются только поля верхнего уровня; история не меняется; сообщение ищется один раз |
| Git/индекс репозитория | Проверка каждого грязного файла разрешала путь и делала лишние вызовы файловой системы; индекс повторно разбирал многомегабайтный JSON | Для отпечатка читаются метаданные файла; один актуальный индекс хранится в памяти процесса |

## Локальные измерения

На этом WSL/NTFS checkout с примерно 50 изменёнными файлами чтение готового
Git-снимка сократилось примерно с **330 до 100 мс**. Повторное чтение готового
семантического индекса сократилось примерно с **430 до 120–150 мс**. Измерения
одиночные, не p50/p95; холодная сборка индекса по-прежнему занимает секунды.

Для искусственного запроса DnD размером 305 КБ тысяча полных `structuredClone`
заняла 113 мс, тысяча вызовов нового `routeBody` — около 1 мс. Это измерение
CPU-операции, а не ускорение целого model turn.

## Где расходуются токены

Самые крупные локальные источники входного контекста: prompt оркестратора Qwen
около 9,2 КБ, SOL около 6,7 КБ; Runtime V3 допускает до 12 000 символов
динамического контекста в `normal` и до 24 000 в `full`. DnD использует отдельный
prompt около 3,5 КБ и два обязательных игровых навыка. Стабильные префиксы
могут попадать в кэш провайдера; фактический расход зависит от истории, схем
инструментов и cache reads. Этот аудит не делал платных inference-вызовов,
поэтому процент экономии токенов не заявляется. Устранённый повтор отклонённого
prompt убирает лишние HTTP-попытки, но их стоимость у провайдера не измерена.

## Ограничения

Без реальной нагрузки провайдера нельзя оценить TTFT, общий turn latency,
стоимость и долю prompt cache. Системный Python без пользовательского пути не
видит `mcp==2.0.0` и `playwright`; для повторных проверок использовано временное
окружение в `/tmp`. Локальная версия Playwright — 1.55.0, а CI закрепляет 1.57.0.
Текущая проверка индекса в памяти рассчитана на один горячий проект;
если параллельная работа с несколькими проектами покажет вытеснение, нужен
ограниченный LRU вместо одного элемента.
