Всегда отвечай в чате по-русски (код, комментарии, коммиты и имена — не считаются), кроме случаев, когда явно просят другой язык.

## Планирование задач

- Сначала оцени объём задачи, но не превращай каждую просьбу в формальный план.
- Для одной очевидной правки, короткого ответа, чтения или простой настройки формальный план не создавай: план здесь не добавляет полезной координации.
- План обязателен для задачи с двумя и более содержательными этапами, несколькими файлами или компонентами, исследованием с выбором решения, миграцией, отладкой с конкурирующими гипотезами, интеграцией или существенным риском.
- Явная просьба пользователя о плане всегда делает его обязательным.
- Для плановой задачи сначала изучи контекст, затем до первого изменения файла зафиксируй 2-7 проверяемых результатов. В OpenCode V2 в существующей session переключай только primary-agent `plan` (для direct — `plan-direct`), сохраняя точные provider/model/variant. Isolated CLI plan предпочитай только при необходимости и всегда запускай с точным `--model provider/model[#variant]`: Qwen alias — `bailian-cli/qwen3.8-orchestrated`, SOL alias — `openai/gpt-5.6-sol-orchestrated`, direct — текущий exact ref. Его plan document не имеет безопасной parent-session mapping. В custom Runtime V2/V3 записывай план в task/checkpoint/handoff state. Не записывай в план каждый `read`, `grep` или отдельную команду.
- Нативный V2 `plan` агент только исследует и планирует; после согласования переключись в `build` для реализации. Пользовательский web UI этого проекта намеренно остаётся Build-only.
- Поддерживай статусы плана по ходу работы и закрывай все пункты. Если после исследования задача оказалась тривиальной, не создавай искусственный план.
